# SNS Media Collector v0.3.3

## v0.3.3：Xアカウント別ログイン

- 「アプリ内Xログイン（アカウント別・推奨）」を追加しました。
- XアカウントごとにWebログイン領域とgallery-dl用Cookieファイルを分離します。
- Cookieは `%USERPROFILE%/SNSMediaCollector/auth/` 以下へ保存し、アプリ更新では削除しません。
- アプリ内ログイン画面から現在のXセッションを保存できます。
- Brave/ChromeのDPAPI復号に失敗する環境向けに、Netscape形式cookies.txtの取り込みも用意しました。
- アカウント編集画面からX認証を実際にテストできます。
- Cookie値を画面やログへ表示せず、アプリの配布物・Gitリポジトリにも含めません。
- 従来のcookies.txt／ブラウザCookie設定は互換用に残しています。

既存アカウントはそのまま引き継がれます。アカウント編集画面で認証方式を
「アプリ内Xログイン（アカウント別・推奨）」へ変更し、ログインまたはcookies.txt取り込みを
一度行ってください。Likesアンカーとarchiveを作り直す必要はありません。

# SNS Media Collector v0.3.0 インストーラー準備版

このパッケージは開発用ソースです。完成したWindowsセットアップEXEはまだ生成していません。
マスターが更新のたびに解凍・Python環境作成・ビルドをする運用を終えるための準備です。

## 目指す利用手順

初回は完成済み `SNSMediaCollector-Setup-0.3.0.exe` を実行します。
その後はスタートメニュー／デスクトップのショートカットから起動します。
更新時は新しいセットアップEXEを実行します。ZIP展開やユーザー側ビルドは不要です。
アプリ内の自動更新は、この初回インストーラー経路が動いた後の段階です。

## 用意した仕組み

- Inno Setupによるユーザー単位インストール。
- アプリは `%LOCALAPPDATA%/Programs/SNSMediaCollector/versions/<version>` へ配置。
- データは引き続き `%USERPROFILE%/SNSMediaCollector`、または既存の指定場所を利用。
- 既存のQSettings名を維持し、認証アカウント・前回の画面・保存先を引き継ぐ設計。
- バージョン別のフォルダに配置し、既存バージョンのファイルを削除せずショートカットを更新。
- アプリの起動中はインストーラーが終了を求める。強制終了は行わない。
- アンインストールにユーザーデータ削除処理を含めない。

## Windows自動ビルド

`.github/workflows/windows-installer.yml` はmainへのpushで動きます。
`build_release.py` が以下を実行します。

1. ソースのテスト。
2. GUIとgallery-dlのWindowsバイナリ生成。
3. 梱包後のアプリ自身によるオフライン検査。
4. セットアップEXEのコンパイル。
5. 一時環境へのインストール → 模擬旧版から更新 → 再インストール。
6. インストール済みアプリの自己検査、アンインストール、データ保持の検査。
7. 全工程成功後だけEXEと検証結果を成果物として保存。

Windows工程はまだ未実行です。専用リポジトリへの接続後、実行してエラーがあれば修正します。
公開リリースを自動作成する処理はなく、GitHub Actionsの権限はcontents:readです。
インストール回帰テストは使い捨てのGitHub Actionsランナーに限定しています。
個人のWindows環境で実行して既存のインストール登録を変更することを防ぐためです。

## 接続に必要なもの

専用の非公開GitHubリポジトリを作成し、READMEを追加して初期コミットを作ります。
ChatGPTのGitHub連携でそのリポジトリを参照・更新できる状態にしてURLを共有してください。
コード登録とビルド結果の確認はこちらで続行できます。
このソース一式にCookie、個人設定、画像、ユーザーDBは含まれていません。

# SNS Media Collector v0.2.3-portable-test

X / pixiv メディア管理ツール。今回はLikes差分取得・保存確認・キューの安定性を整えた版です。
ブックマーク本文の閲覧機能はまだ実装していません。

## 最初の起動

1. ZIPを新しいフォルダに展開します。
2. `setup_and_run.cmd` でソース版を起動できます（Python 3.10以上）。
3. EXEで使う場合は `build_portable.cmd` を実行してください。
4. ビルド完了後に開くExplorerの `SNSMediaCollector` フォルダにある
   `SNSMediaCollector.exe` を起動します。以後の通常起動はこのEXEだけです。

ビルド先は `portable_build/v0.2.3-<ランダム番号>/SNSMediaCollector/` です。
既存のビルド成果物は削除せず、新しいフォルダへ作成します。
EXEだけでなく、このフォルダ全体（`_internal`、`bin`等）を一緒に置いてください。
完成済みWindows EXEはこのZIPには含まれません。自動アップデート機能も未実装です。

## 設定の引き継ぎ

設定・認証プロファイル・アンカー・archive・カタログは従来どおり
`%USERPROFILE%/SNSMediaCollector` にあります（データ保存先を変更している場合はその場所）。
アプリ本体を入れ替えてもこの場所は変わりません。
Cookieをチャットへ送る必要はありません。既存のローカル認証設定を使用します。
アカウントと取得対象のJSON保存は、一時ファイルを完全に書いてから置き換える方式へ変更しました。
検証用の起動は専用ディレクトリの設定ファイルを使い、普段のWindows設定を変更しません。

## v0.2.3：前回のアカウント・取得画面を復元

登録した認証設定に加え、選択中のアカウント、サービス、取得対象のURL／@ID、
いいね／メディア等の種類、保存先、取得範囲、画像・動画等の選択を記憶します。
画面の変更後と終了時に保存し、次回起動時に復元します。自動ダウンロードは開始しません。
まず一度いつもの設定にしてから終了・再起動してください。

既存のアカウント登録は引き継ぎ、内部識別子を追加します。同じ表示名のアカウントも区別します。
アカウントを追加・編集しても先頭へ戻らず、編集したアカウントを選択した状態にします。
保存されていたアカウントが削除済みの場合は、別の認証へ勝手に切り替えません。
画面設定には認証内容を複製せず、登録済みアカウントの識別子を保存します。
前回の画面を1組記憶する機能です。アカウントごとの複数プリセットは未実装です。

## v0.2.2 の追加改善

`build_portable.cmd` は、梱包後のアプリを `--self-test` で起動して検証します。
画面生成、PNG表示、SQLiteの再読込、同梱gallery-dl起動、X/pixivモジュールの存在を検査し、
どれかが失敗したらビルド成功とは表示しません。結果はビルド先の `portable_self_test.json` に残ります。
検査は一時ディレクトリを使い、普段の設定・Cookie・画像には触れません。
この検査はログインや外部サイトとの通信を行いません。

起動時のエラー処理も、コンソールのないWindowsアプリでログ出力が二重に失敗しないよう修正しました。

## v0.2.1 から引き継いだ改善

- Likes候補をメディア単位でarchive／既存Hitomiファイルと照合。
  全件取得済みなら取得ジョブを作らず「新規なし」と表示します。
- 1投稿の画像1枚が取得済みでも、残りの画像まで取得済みとは判定しません。
- 正常終了だけではアンカーを進めず、候補全件の取得状態を確認します。
  境界更新後はDBを再読込し、先頭投稿IDをログで確認できます。
- 一部失敗・中断・ファイル欠落・照合失敗なら境界を保持して次回再確認します。
- 保存件数はエンジンが通知した、保存先内の実在する非空の新規ファイルだけ。
  同じフォルダに別アプリが作った画像は加算しません。
- 起動不能のエンジンも終了状態へ移し、キューを進めます。
- ユーザーの停止を成功として扱わず、アプリ終了時に次のジョブを開始しません。
- 「保存先から表示」は別ウィンドウにし、ダウンロード履歴に追加しません。
  旧版が履歴に混ぜた画像は識別できないため、その履歴は保持しています。
- 日本語パスを含むエンジン出力をUTF-8で受け取ります。

## 今回の実機チェック

「新しいいいねだけ」で取得 → 完了後もう一度実行してください。
取得済みなら「新規なし」、未取得があれば取得確認ジョブが表示されます。
ログの `[LIKES CHECK]`、`[LIKES ANCHOR MOVE]`、`[SAVED OK]` が確認箇所です。

形式フィルターで除いた画像など、取得を確認できない候補が残るとアンカーを保持します。
その場合は同じ候補を次回も再確認します。archiveをOFFにしてHitomi互換名も使わない設定では、
取得済みの対応を確定できず保留になる場合があります。通常はarchiveをONにしてください。
アンカーが見つからない場合も従来どおり過去の全件取得へ自動移行しません。
